# CareerOS V1 Customer Onboarding Flow

1. Account and profile creation: user confirmation required.
2. Resume, profile export, manual history, portfolio, project, certification, or education intake: user supplied; optional source types.
3. Deterministic CareerFact extraction: automatic proposal, provenance required.
4. Evidence association: automatic proposal; user confirmation required for authority-bearing promotion.
5. Canonical capability derivation: automatic derived projection; fail closed on unsupported scope or specialist claims.
6. Active learning: automatic selection of approximately 5-15 questions from uncertainty, recurrence, scope, specialist sensitivity, and evidence availability.
7. Capability profile: generated after neutral/unresolved states are preserved.
8. First job input: URL, pasted description, or saved posting; user confirmation required for source identity.
9. Match evaluation and explanation: automatic after source and profile authority are available.
10. Return path: new source, correction, project, credential, or user decision creates a versioned update, not an upstream overwrite.

## Normal path

No StaffordOS operator intervention. Customer confirmation is required for authority-bearing career claims and corrections.

## Exception path

Ambiguous source identity, conflicting evidence, unsupported specialist claims, privacy requests, or failed provenance become `UNKNOWN`, `NEEDS_MORE_EVIDENCE`, or a customer-visible review state.

## Operator/admin path

Only for support, abuse, legal deletion/export operations, or product incident response. Operators cannot silently alter customer capability authority.

Expected burden: initial 5-15 questions; new job normally 0 questions; changed career history 0-5 targeted questions; returning user only reviews newly uncertain capabilities.
